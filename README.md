# mip-erc7496-midnight-contracts

The reference implementation of **[MIP-0018, "On-Chain Token Metadata
Emission"](https://github.com/midnightntwrk/midnight-improvement-proposals/pull/325)**
(MIP PR #325, `mips/mip-0018-on-chain-token-metadata.md` @ `37a3471`): a Compact
module and reference contracts that publish a token's `name`, `symbol`,
`decimals` and arbitrary key/value traits as contract events, so an indexer can
build a token table without a registry and without trusting anyone but the
emitting contract.

Midnight tokens are ERC-1155-like — one contract mints many tokens, each keyed by
a 32-byte *domain separator*, and the token's colour (its type) is
`persistentCommit([domainSep, contractAddress], pad(32, "midnight:derive_token"))`.
Nothing on chain says what a colour means. The MIP fixes that with one event
shape, in the spirit of [EIP-7496 (NFT Dynamic Traits)](https://eips.ethereum.org/EIPS/eip-7496).

**The MIP is the standard.** [`TOKEN-METADATA.md`](./TOKEN-METADATA.md) points at
it and records how this repository implements it — UC-1 (the amendment in
development this branch implements), the module's API, the emitter secret, the
`repository` key, the legacy event name still on chain, the measured circuit cost and
the fixtures. This file is about building and running what is here.

The event a conforming contract emits is a `Misc` event named
`pad(32, "mip-0018:token-metadata[v1]")`. On this branch it follows **UC-1**, an
amendment in development (the MIP text is unchanged; see TOKEN-METADATA.md): the event
opts into the Multi-Part Event rule, so the unit a consumer decodes is a **package** —
every such event of one contract in one intent, merged in emission order, `256·k`
bytes — and every package carries exactly ONE declaration:

```
offset  0  32  domainSep    the token within this contract
offset 32   1  kind         0 unshielded native · 1 shielded native
                            2 unshielded ledger · 3 shielded ledger
offset 33  32  key          key bytes, NUL-padded; a `/metadata/` key must be
                            a valid RFC 6901 JSON Pointer
offset 65   1  val-type     0 opaque · 1 string · 2 integer (Uint<8*val-len>,
                            little-endian, 1..31 bytes) · 3 ONE complete JSON
                            value · 4 absolute URI · 5 Null (val-len 0)
                            6..255 reserved — reject
offset 66   2  val-len      Uint<16>, little-endian: 0..65535, 68 + val-len <= 256·k
offset 68   …  value        188 bytes fit one event; a longer value is one
                            declaration in ceil((68 + val-len) / 256) parts
```

Who may emit: every contract here stores the hash of an **emitter secret** at
construction and checks it in every emitting circuit (TOKEN-METADATA.md, "The emitter
secret").

**The event name is the layout version.** The reference set on Stagenet was
deployed while the MIP number was still unassigned and emits
`mip-xxxx:token-metadata[v1]`; a conforming v1 consumer *ignores* those events
and nothing was redeployed — see TOKEN-METADATA.md, "The legacy name".

Status: **experimental**, tracking a Proposed MIP.

## Layout

```
TOKEN-METADATA.md                    pointer to the MIP, UC-1, implementation notes

contracts/NativeShieldedToken.compact    one static domain, shielded  (kind 1)
contracts/NativeUnshieldedToken.compact  one static domain, unshielded (kind 0)
contracts/NativeDualToken.compact        one domain, both kinds (0 and 1)
contracts/ShieldedCollection.compact     one address, one domain per piece
contracts/LedgerToken.compact            balances in contract state (kind 2)
contracts/probe/MetadataProbe.compact    the byte-layout proof; emits arbitrary payloads and packages
contracts/generated/<ID>18.compact   the MIP-18 set (generated): LSUN18 … LLIAR18
contracts/managed/<name>/            compiled output (see below)
scripts/compile.sh                   compile with the pinned toolchain
scripts/circuit-cost.sh              report k and rows without generating keys
scripts/generate-literal-contracts.ts  the reference set as the literal-payload MIP-18 set
scripts/export-simulator-fixtures.ts   the offline fixture corpus (runs the MIP-18 set)
scripts/deploy-and-publish.ts        deploy the MIP-18 set (local chain or Stagenet, MN_*)
scripts/stranger-check.ts            a caller without the emitter secret cannot emit
fixtures/simulator/                  the offline corpus, regenerated by that script (SOURCE.md)
fixtures/legacy-mip-xxxx/            the frozen `mip-xxxx` corpus of the #315 draft
fixtures/stagenet/                   the on-chain record of the Stagenet deployment
test/token-metadata.ts               the payload decoder, the validator and the simulator harness
test/*.test.ts                       the tests
minocrab/                             historical MinoCrab metadata fixtures and evidence
benchmarks/                           historical Compact/MinoCrab measurement reports
```

Each template composes the metadata module (with its emitter secret) and, where one
exists, an OpenZeppelin token module — `@openzeppelin/compact-contracts@0.4.0-alpha.3`,
whose sources declare `pragma language_version >= 0.26.0` and therefore compile under
this toolchain (its shielded `_mint` takes a `ZswapCoinPublicKey`, OZ #833, so the
templates' mints do too). OpenZeppelin has no native *unshielded* token module, so
`NativeUnshieldedToken` calls the standard library's `mintUnshieldedToken` directly.

Deliberate design points:

- **One emitting circuit per template, one declaration per call** (UC-1): the setter
  (`setMetadata` / `setPieceTrait`, `valLen: Uint<16>`, `value: Bytes<188>`). `name`,
  `symbol` and `decimals` are three calls — three intents, three packages.
- **Only the emitter can emit**: the constructor's first argument is the emitter-secret
  hash and the setter checks the secret first. `LedgerToken` keeps OpenZeppelin
  `Ownable` for its owner-only `mint`.
- **Minting is not gated** on the native templates. These are reference test tokens.
- **`name` and `symbol` as `Opaque<"string">`** go to the OpenZeppelin constructors for
  their `name()`/`symbol()` circuits; Compact cannot serialise an opaque host value into
  a circuit, so the event path takes the byte form as setter arguments.

The contracts that are actually deployed are the **generated MIP-18 set** (below):
literal payloads, standard-library mints, no OpenZeppelin module (spec 00024 Q17).

## Toolchain

Compact **0.34.0** (language 0.26.0, runtime 0.19.0, Midnight ledger 9). It is
installed *beside* whatever the machine's default is:

```sh
compact update --no-set-default 0.34.0   # leaves `compact compile --version` alone
compact compile +0.34.0 --version        # -> 0.34.0
```

`scripts/compile.sh` always calls `compact compile +0.34.0`, so building this
repository never changes the host's default compiler.

Node ≥ 22.12 (`.nvmrc` says 24).

## Compile

```sh
./scripts/compile.sh                      # all contracts, with proving keys
./scripts/compile.sh NativeShieldedToken  # just one
SKIP_ZK=true ./scripts/compile.sh         # no proving keys — seconds instead of minutes
./scripts/compile.sh --check              # does contracts/managed/ still match the sources?
```

Contracts are compiled **one at a time**: proving-key generation is this
toolchain's memory peak. The script prints available memory before each contract
and refuses to generate keys below 1.5 GiB.

### The `managed/` tree

Committed: the generated TypeScript (`contract/`), the ZKIR (`zkir/`) and the
compiler metadata (`compiler/`). **Not** committed: `keys/`. A single k=19
proving key is 134 MB, both key kinds are a pure function of the committed ZKIR,
and `./scripts/compile.sh` regenerates them in minutes. `--check` compares
everything except `keys/`. Known limit: the committed source maps list absolute
`sources` paths of the clone that compiled them (despite `--sourceRoot`), so `--check`
matches only in that clone's path; and `--check` implies `--skip-zk`, so it cannot match
a contract committed with keys (the generated set embeds `expectedVk`).

## Proving cost — read this before deploying

Emitting an event whose payload is built from **runtime** values (ledger fields
or circuit arguments — i.e. any real token's metadata) is expensive in ZKIR v2.
Measured with `./scripts/circuit-cost.sh`, which runs `zkir mock-compile` and
needs no keys:

| what is emitted | ZKIR v2 (default) |
|---|---|
| one literal one-part declaration, no emitter check | k=6, 23 rows |
| one literal three-part declaration, no emitter check | k=7, 23 |
| any literal declaration with the emitter check (the MIP-18 set, 1–3 parts) | k=13, 4 162 |
| one runtime byte, the rest literal (pre-UC-1 measurement) | k=15, 26 422 |
| the templates' setter: runtime `Bytes<188>` + the emitter check | k=19, 332 210 |
| a runtime two-part package (probe only) | k=19, 494 583 |

The emitter check (a SHA-256 over the witness secret) is ~4 100 rows, so a literal
emitting circuit is k=13 whether it emits one part or three. ZKIR v3 measured ~4.4×
cheaper across the board (pre-UC-1).

For scale, OpenZeppelin's shielded `_mint` is k=14 and its `_burn` k=16.

Consequences, all of them already applied here:

- **One declaration per call** (UC-1). A long value is still one call: it emits every
  part. One circuit per declaration, except the collection (one selector circuit per piece):
  a deploy writes every verifier key and the local chain allows 50 000 bytes written per
  block, so a contract keeps ≤ 20 proof circuits.
- **Key generation for the generated set is quick** (k ≤ 14: the eleven contracts, ~100
  circuits, compile with keys in about seven minutes). The templates are compiled
  without keys; a k=19 circuit takes about six minutes of `zkir` and a 134 MB key.
- **ZKIR v3 is uniformly ~4.4× cheaper** and is one switch away
  (`ZKIR_V3=true ./scripts/compile.sh`), but nothing here has yet shown that a
  live Midnight network and proof server accept a v3 verifier key. Settle that
  with a single probe deployment before relying on it.
- **The contracts that are actually deployed are the generated literal ones.**
  They emit byte-identical payloads — `test/generated.test.ts` asserts it
  against the parameterised template — for two orders of magnitude less proving
  work.

### Historical MinoCrab benchmarks

[`minocrab/`](./minocrab/README.md) and [`benchmarks/`](./benchmarks/) preserve
the earlier Compact/MinoCrab comparison and a typed-shape experiment at their
audited source pins. They are historical fixtures: both use the legacy
`TokenMetadata` event name and `Bytes<16>` symbols. The typed experiment happens
to use a 189-byte value, but its tags are benchmark-local. Neither suite measures
the current `mip-0018:token-metadata[v1]` implementation above (the UC-1 layout: a
2-byte `val-len`, `Bytes<32>` symbols, a `Uint<128>` `decimals`). Their pinned
`compact-src/` snapshots are reproducibility artefacts and are deliberately left
at their audited revision.

## Test

```sh
npm test          # vitest, in-process Compact simulator, no network, no proof server
npm run typecheck
```

The tests run every template, the probe and every generated contract through
`@midnight-ntwrk/compact-runtime`, group each call's `Misc` events into packages (one
call = one intent) and check them against the MIP and UC-1 — the decoder and validator
in `test/token-metadata.ts` deliberately re-implement sections 1, 2.1, 2.2, 3 and 5.1
and UC-1 from the text rather than importing anything from the contracts, so a
disagreement fails a test. They also check that a caller without the emitter secret is
refused by every emitting circuit.

They also check the two properties an indexer depends on: the colour derived off
chain from `(domainSep, address)` equals both the contract's `tokenColor()` and
the colour of the coin it actually mints, and a ledger token's `transfer`
produces no mint effect at all.

One detail worth knowing if you read log events in process: the VM hands over
the 288 serialized event bytes as an aligned value with **trailing NULs
trimmed**, while declaring `length: 288`. Zero-extend before slicing
(`rawMiscBytes` does). An indexer reading `MiscContractEvent.payload` over
GraphQL gets the full 256-byte payload already re-padded.

## The reference set, the MIP-18 set and the fixtures

[`deployments/reference-set.json`](./deployments/reference-set.json) is the
reference deployment as data: eleven rows across all four families, including
the cases a token table has to render and nobody remembers to build — a token
minted before it is described, one described but never minted, one minted and
never described, and one that describes its ledger side and then mints natively
anyway. Every metadata step
carries the `val-type` of MIP section 2.1, and the generator refuses to write a
payload a conforming consumer would have to reject: a reserved val-type, a
non-UTF-8 string, an integer outside 1..31 bytes, a JSON value that is not one
complete value, a relative URI, a Null with a non-zero length, a `/metadata/` key
that is not a valid RFC 6901 pointer, or a symbol over 32 bytes.

`scripts/generate-literal-contracts.ts` turns it into **the MIP-18 set** — the `18`
variant of every row (spec 00024 §6.A): ids, symbols, names and domain separators carry
the suffix, every declaration is a circuit of its own (one declaration per intent), a
value longer than 188 bytes is one circuit emitting all of its parts (a collection has one
circuit per piece whose public selector `which` picks one literal declaration per call, so
its deploy fits one block — TOKEN-METADATA.md, "Circuit cost"), and, where possible,
every token a contract describes also declares `repository` (val-type 4) — the URL of the
contract's own file on `main`, `https://github.com/acedward/mip-0018-midnight-contracts/blob/main/contracts/generated/<ID>.compact`.
`SGHOST18`, the minted-only row, declares nothing at all (not even `repository`: a token
need not be on GitHub, spec 00024 Q19) and stays `observed`. The only constructor argument
is the emitter-secret hash.

| `SOURCE.md` | generated: toolchain, stand-ins, SHA-256 of every input and output |

Contract addresses are `sha256("umbra:00024:<ID>")`, one stand-in transaction per call
(`sha256("umbra:00024:sim:<row>:<step>")`, segment 1), so every byte — including every
colour — is reproducible, and two runs give identical files. An indexer can be written
and tested byte-exactly against this corpus long before a chain is involved.

One subtlety the corpus encodes: a token row is keyed by
`(address, domainSep, kind)` with the **full** kind byte (MIP section 4), and
`privacy`/`storage` are derived from it rather than stored beside it. So the
"Ledger Liar" row, which declares kind `2` and then mints natively, is **two**
rows: an `observed` kind-0 row with no name and a `declared` kind-2 row with
one. Neither can hide or relabel the other, which is exactly the point of MIP
section 6.3.

### `fixtures/legacy-mip-xxxx/` — the frozen draft corpus

The same five files as `fixtures/simulator/`, as they were produced against the
**#315 draft** under the `mip-xxxx:token-metadata[v1]` placeholder name. They are
never regenerated and nothing in this repository's tests reads them; they exist

## Deploy

`scripts/deploy-and-publish.ts` deploys the MIP-18 set and runs each row's steps, **one
circuit call per transaction** (so each declaration is its own intent). It takes its
network from the `MN_*` variables, so a deployment elsewhere needs no code change. The
spec 00024 set is deployed on a **local Midnight 2.x chain** (node 2.0.0-rc.4, indexer
4.4.0-rc.3, proof server 9.0.0-rc.6); a Stagenet deployment of this branch has not been
made.

### 1. A chain, a proof server, a funded wallet

The local dev chain of the Umbra project (a Docker Compose stack; not part of this
repository) provides all three: the node, the indexer, a proof server on its private
network, and a BIP-39 test wallet funded from the dev chain's genesis and registered for
DUST (a Midnight transaction pays its fee in DUST, which NIGHT generates only once its
UTxO is registered).

### 2. Generate, compile, deploy

    npx tsx scripts/generate-literal-contracts.ts      # contracts/generated/*18.compact + the matrix
    ./scripts/compile.sh generated/SSTAR18             # with keys (k <= 14: seconds each)

    MN_NETWORK_ID=undeployed \
    MN_INDEXER_URL=http://indexer:8088/api/v4/graphql MN_INDEXER_WS_URL=ws://indexer:8088/api/v4/graphql/ws \
    MN_NODE_URL=http://node:9944 MN_NODE_WS_URL=ws://node:9944 MN_PROOF_SERVER_URL=http://proof-server:6300 \
    MN_MNEMONIC_FILE=/secrets/test-wallet.mnemonic \
    MN_EMITTER_SECRET_FILE=/secrets/emitter.secret \
    MN_PRIVATE_STATE_DIR=/secrets/private-state \
    MN_DEPLOYMENT_FILE=out/local-deployment.json \
      npx tsx scripts/deploy-and-publish.ts LSUN18 LMOON18 SSTAR18 SNEB18 SGHOST18 UCOM18 UMET18 UPROM18 DAUR18 CNST18 LLIAR18

With no row arguments every non-optional row runs (`LLIAR18` is optional). The script
is **resumable per row and per step**: the deployment record (`MN_DEPLOYMENT_FILE`,
default `out/deployment.json`; `out/` is not committed) holds the address, the
emitter-secret hash and each completed step (for an emit step: the key, the part count
and the SHA-256 of the package bytes), and a re-run skips them. A failing step stops
that row only.

**The emitter secret.** `MN_EMITTER_SECRET_FILE` is a mode-600 file holding 32 bytes as
hex. The constructor of every contract gets `emitterSecretHashOf(secret)`; the secret is
the contract's private state (`{ emitterSecret }`), which midnight-js keeps in a LevelDB
named `midnight-level-db` in the working directory — `MN_PRIVATE_STATE_DIR` moves the
process into a directory of your choice for it (it also holds the contracts' maintenance
signing keys). Prove on a proof server you run: it sees the secret.

**The stranger check.** `scripts/stranger-check.ts` (same variables, no
`MN_EMITTER_SECRET_FILE`) finds every deployed contract of a record again with a fresh
random secret and calls every emitting circuit: each call must fail with
`TokenMetadata: caller is not the emitter`, before any proof or transaction exists, and
no contract's latest action may change.

### Stagenet

`MN_NETWORK_ID` unset is the Stagenet profile (`MN_SEED` hex, the Stagenet URL
defaults); `scripts/register-dust.ts` registers a Stagenet wallet for DUST. The 2026-09-18
Stagenet deployment described above predates UC-1 and emits the legacy placeholder name;
`scripts/export-fixtures.ts` is its recorder.
